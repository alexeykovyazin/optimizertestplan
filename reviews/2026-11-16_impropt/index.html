Седьмое ревью оптимизатора v5.0-impr-opt

Ошибок результата нет. Два новых коммита — формула OR и распределения текстовых BLOB — дали восемь ошибок оценки. Все восемь исправлены в PR #30, он принят. После обновления сборки нужен REFRESH STATISTICS: без него запросы с фильтром по BLOB на CEB медленнее до 14 раз.

2 новых коммита + слияние PR #28 база сравнения b69da49179 сборка Windows x64 от 16.11, embedded isql; CEB — dellg15 новые находки Z1–Z12 исправления: PR #30 (принят, 6df82603c4)

1Главное

  • Ошибок результата нет. Тесты 00–60: новых ошибок нет, матрица 42 — 198 из 198. 1 200 случайных запросов совпали со штатным HQbird 5.0. Четыре полных прогона CEB дали одинаковые контрольные суммы.
  • PR #28 принят вместе с Y7. Коммит включил цену BLOB по байтам. На CEB MOVIE_INFO уходит в конец порядка соединения: 11a_009 — 107.7 с вместо 7.7 с, 11a_011 — таймаут 300 с.
  • b2800ecb7d исправляет это только после ALTER DATABASE REFRESH STATISTICS. Без REFRESH 11a_009 — 121 с и 146.9 млн fetches; после него — 4.6 млн fetches.
  • Z1: новая формула OR изменила режим по умолчанию. a = 0 or a = 1 — 77 596 строк при 100 000. Документация обещает, что без PredicateCorrelation оценки не меняются.
  • Z4, Z5: статистика текстовых BLOB. При SAMPLE длинные значения считаются NULL: b is null — 18 000 строк при 0. Доля распределения завышена: b = 'short' — 20 000 при 2 000.
  • CEB быстрее. Сборка PR #30: 118 из 121, геом. среднее времени ×0.83 к b69da49179 и ×0.99 к b2800ecb7d.
  • Пять запросов CEB медленнее b69da49179 в 3–10 раз: 11b_005, 11b_012, 9a_014, 9a_015, 9a_004. Они появились в b2800ecb7d; причина не разобрана.
  • Исправления приняты: PR IBSurgeon/hqbird#30, 9 коммитов, одна проблема — один коммит.
