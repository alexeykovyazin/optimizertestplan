# CEB 7a_002: медленный план на v5.0-impr-opt-fix

Скрипт `Repro-7a002.ps1` воспроизводит регресс запроса 7a_002 на базе IMDb (Windows PowerShell 5.1 или 7, isql).

## Проблема

- Сборка с исправлениями ревью 05.11 (ветка v5.0-impr-opt-fix, `9817c01bef`) выполняет 7a_002 за **~40 с**.
- В прогонах 4 и 5 этот запрос выполнялся за 6.4 и 5.9 с. Результат везде одинаковый: COUNT = 7986.
- **Причина.** Теперь в стоимость входят локальные фильтры таблиц на внутренних позициях соединения (CR1). Для двух видов фильтров оценки по умолчанию в 2–4 раза ниже реальных:
  - числовой текст `(info = '' OR info SIMILAR TO ...) AND CAST(info AS DOUBLE PRECISION) ...`;
  - `kt.kind IN ('episode','movie')`.
- Из-за этого цепочка соединений от MOVIE_INFO_IDX (MII1) выглядит дешёвой. Путь от NAME (N) на самом деле быстрее примерно в 6 раз.

## Запуск

```
powershell -ExecutionPolicy Bypass -File .\Repro-7a002.ps1
powershell -ExecutionPolicy Bypass -File .\Repro-7a002.ps1 -Server localhost/3050 -Database D:\data\imdb.fdb -RunsPerQuery 1
```

- **Параметры** задаются в блоке `param()` в начале скрипта:
  - `-IsqlPath`, `-Server`, `-Database`, `-User`, `-Password` — подключение;
  - `-RunsPerQuery` — число запусков каждого запроса;
  - `-TimeoutSeconds` — предельное время одного запуска;
  - `-SlowFactor`, `-BadEstimateFactor` — пороги для вывода.
- **Коды выхода:** 1 — проблема воспроизведена, 0 — нет, 2 — ошибка.
- Шагу 2 нужна сборка, которая показывает оценки строк в EXPLAIN (ShowExplainCardinality). На других сборках этот шаг выводит «no estimate», остальные шаги работают.
