## 6. Миграция хранилища STAT$ (W4)

Формат STAT$ между 06041718cc и b69da49179 **не менялся**: база любой из двух сборок работает на другой без
REFRESH. Но хранилище от a3cfa97218 (08.11) и старше по-прежнему ломает все запросы. На dellg15:

```
select count(*) from TITLE;
-- Statement failed, SQLSTATE = 42S22: Column unknown STAT$BLOB_LEVELS
```

Миграция, проверенная на dellg15 (REFRESH — 66 с; 108 колонок и 23 именованные структуры сохранены):

```sql
ALTER TABLE STAT$COLUMNS
  ADD STAT$BLOB_LEVELS BLOB SUB_TYPE BINARY,
  ADD STAT$BLOB_LEVELS_TEXT BLOB SUB_TYPE TEXT CHARACTER SET UTF8,
  ADD STAT$BLOB_AVG_PAGES DOUBLE PRECISION,
  ADD STAT$BLOB_MAX_PAGES INTEGER,
  ADD STAT$BLOB_AVG_LEN DOUBLE PRECISION,
  ADD STAT$BLOB_MAX_LEN BIGINT,
  ADD STAT$SUB_TYPE SMALLINT;
COMMIT;
ALTER DATABASE REFRESH STATISTICS;
```

ALTER выполняется на новом движке: DDL работает, не работают только запросы к таблицам пользователя и STAT$*.
Автомиграции и подсказки в сообщении нет; документация по-прежнему советует DROP + ADD, который теряет
именованные структуры.
