Шестое ревью оптимизатора v5.0-impr-opt

Все три критичные ошибки ревью 12.11 закрыты, CEB стал вдвое быстрее прогона 4. Но 31 новый коммит добавил две ошибки результата: Batch Hash Join теряет строки, а LIKE без масок теряет строки при коллациях CI / AI. Исправления готовы: PR из 23 коммитов.

31 коммит база сравнения 06041718cc сборка Windows x64 от 15.11, embedded isql; CEB — dellg15 новые находки Y1–Y20 исправления: PR #28

1Главное

  • Исправления 12.11 работают. W1: тест 35 верен, матрица 42 — 198 из 198. W2: сервер не падает на записях до 1 МБ. W3: 14 100 запросов с escape совпали со штатной сборкой. Закрыты W5, W6, W7, W12, W13, W14, W17, W19.
  • CEB быстрее. Полный прогон, 121 запрос: геом. среднее времени ×0.53 к прогону 4 и ×0.86 к прогону 5. 7a — 123 с вместо 239 с (08.11).
  • Y1: Batch Hash Join теряет строки (8a574656ba): 2 500 вместо 20 000. Нужен BHJ и ведущая сторона, где в батче не больше 16 384 строк с ключом: редкий FK в большой таблице. Конфиг по умолчанию — то же.
  • Y2: LIKE без масок теряет строки при CI / AI без индекса: ai like 'сергеи' — 1 строка вместо 3. Ошибка ветки с 10.11 (381231c716); прошлые ревью её не нашли.
  • Запросы падают: Cannot transliterate при выполнении LIKE у клиента WIN1251 (Y3); PREPARE s like 'Мо0а' — string right truncation (Y4). W4 не исправлен: хранилище STAT$ от 08.11 ломает все SELECT.
  • Скорость: LEFT JOIN с view — 2 млн fetches вместо 500 (Y5); FULL JOIN с подзапросом в ON — 9.5 с вместо 0.08 с (Y18); подзапрос с границей-подзапросом — 12.7 с вместо 0.005 с (Y20).
  • Исправления готовы: PR IBSurgeon/hqbird#28, 23 коммита, одна проблема — один коммит. Итоговая сборка совпала со штатной на 1 200 случайных запросах.
  • Открытый вопрос: запрос CEB 9a_002 в полном прогоне вернул 7 строк вместо 28; 16 повторов дали 28. Причина не найдена.

8Миграция хранилища STAT$ (W4)

Формат STAT$ между 06041718cc и b69da49179 не менялся. Хранилище от 08.11 и старше ломает все запросы: Column unknown STAT$BLOB_LEVELS. Миграция проверена на dellg15: 108 колонок и 23 именованные структуры сохранены.

ALTER TABLE STAT$COLUMNS
  ADD STAT$BLOB_LEVELS BLOB SUB_TYPE BINARY,
  ADD STAT$BLOB_LEVELS_TEXT BLOB SUB_TYPE TEXT CHARACTER SET UTF8,
  ADD STAT$BLOB_AVG_PAGES DOUBLE PRECISION,
  ADD STAT$BLOB_MAX_PAGES INTEGER,
  ADD STAT$BLOB_AVG_LEN DOUBLE PRECISION,
  ADD STAT$BLOB_MAX_LEN BIGINT,
  ADD STAT$SUB_TYPE SMALLINT;
COMMIT;
ALTER DATABASE REFRESH STATISTICS;
